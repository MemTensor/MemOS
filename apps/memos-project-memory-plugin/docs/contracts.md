# 实现契约

## 项目概览按 Space 缓存（2026-11-24）

概览唯一来源改为 SQLite `project_overviews(scopeId,connectionId,spaceId,content,fetchedAt)`。新建／绑定立即拉取；session-start 仅对未获取或超过6小时的项刷新，宿主能力决定等待还是返回旧缓存。普通事件不读取云概览，无定时器／新路由／等待参数。解绑同事务删缓存，在途结果复核原绑定时间和连接；旧 sessions.overview 不反拆、不作为缓存读取。中途对话创建／绑定的原响应携带 overview，具体规则见 [概览缓存](overview-cache.md)。

## 双协议云连接（2026-11-23）

连接显式配置 apiMode、baseUrl、authMode、cloudProjectId，接口类型和地址由本地服务配置管理。工程旧配置默认 engineering/token；Viewer 保存时两种接口默认使用 Token；算法创建和写入的 cloudProjectId 默认使用当前接口要求的 `test1`；配置缺失或空值在加载时补齐默认值，切换协议保留已有自定义项目 ID。协议映射、连接归属、只读测试与开放 Episode 语义见 [云服务访问配置](cloud-access.md)。检索响应若标记 degraded 含 project，即使 HTTP 成功也视为不可用，不返回 EMPTY。

## 历史容量组批与独立轨迹确认（2026-11-23）

`Config.uploadMaxBytes` 是唯一上传容量配置，默认39000字节，正安全整数；原配置缺失时补默认。大小按最终 add/message 请求体 JSON 的 UTF-8 计算，包括路由字段，组批和发送使用 `messageRequest` 同一构造方法。实时原始快照继续整轮保存，历史补传允许同一轮次多批，但不跨云端 conversation_id 混合会话。

历史扫描只保存索引及原始时间/父子关系元数据。显式上传依会话原始时间逐个物化，复用已有同步周期和 historyUploads 进度，单批接收并处理完成才继续；暂停、恢复及配置缺失沿用既有控制。前端从最新绑定状态读取独立待处理轨迹数，超过配置项 historyUploadConfirmCount 才确认（默认100），等于阈值不确认；同一源记录的多空间投递不重复计数。上传中禁用按钮，终态显示“已完成”，不把静默跳过误报为全部已上传。

超大单条及维护其工具关联所需的对应操作只标记内部 skipped，正文完整留在 SQLite，不弹窗、不显示失败、不消耗发送次数、不编造 task_id。新增状态复用 batches/batch_traces/batch_deliveries，无新表。来源投影成多条消息时，覆盖必须由该目标全部对应的成功或跳过消息共同满足；部分成功只补缺失消息。不同 Space 回执、内容顺序、可靠 ID 及已发送快照保持不变。

首次发送前按当前配置复核，未尝试的历史批次可重新组批；已尝试快照不改写。绑定授权固定到请求时的目标及 boundAt，新增空间不自动加入，解绑重绑不恢复旧任务。旧未尝试容量阻塞在用户再次上传时退役并补传；重启保留既有队列/回执，未物化原生历史由显式扫描和上传恢复，不新增启动扫描或后台定时器。

失败后的显式补传复用上传接口与确认配置。`history.canUpload` 单独表示能否提交，`uploadError` 仅呈现失败原因及配置阻塞；本次运行优先显示 uploading，旧错误不盖住进度。调度记录当前批次 ID，只检查该批次及其后续替代批次的新失败，不让旧失败在多批覆盖完成前中断补传。旧尝试次数、已发送快照、已成功目标的回执保持不变；已获 task_id 的云端处理失败不自动重新发送。

## 对话解绑项目空间（2026-11-23）

解绑 Skill `memos-unbind-project-space` 处理用户明确要求取消当前项目关联并给出 Space ID 的意图；缺 ID 只询问 ID，不凭名称猜测。CLI `memos-pm unbind --space-id` 不接收身份路由参数，复用 projectContext、原生宿主环境和同一本轮专属入口，不新增环境变量、目录、表、缓存或依赖。

`POST /api/unbind-project {context,spaceId}` 复用当前项目查询的准确 Agent＋项目定位，随后调用 Store.unbind 原事务。只删除指定本地关联、取消该目标未完成投递，最后一个空间关闭采集窗口；无 Key、暂停或更换云配置不阻止本地解绑，不访问云端。其他 Space 和其他 Agent／项目保留。返回缓存名称和剩余 spaces；未绑定为成功 NOT_BOUND 且不创建新项目／绑定记录。已发送请求无法撤回，按现有逻辑保存真实结果，不复活取消队列。

独立解绑调用及可靠 ID 对应结果共用现有绑定控制过滤与最小身份记录；实时／历史／Codex缓存／上传使用同一规则，同轮业务与示例保留，混合动态脚本保守保留，已发送快照不改写。Viewer 原有解绑接口不变。详见 [解绑契约](../skills/unbind-project-space/references/cli-contract.md)。

## 对话查看本地项目空间（2026-11-23）

查看空间 Skill `memos-list-project-spaces` 根据当前上下文中的绑定查询意图触发，覆盖“项目、空间、组织、关联到哪里”等表达，不新增同义词匹配代码。`memos-pm spaces` 零参数，复用绑定的宿主身份解析、冲突校验和本轮专属入口；不会按工具目录或最近会话推断目标，创建、绑定入口契约保持兼容。

本地 `POST /api/project-spaces` 按有效当前轮身份，优先固定会话项目，否则按最长目录匹配。只调用 `Store.spaces` 返回本地名称和 ID，零云请求、不要求 Key。未登记或已解绑为 EMPTY，身份缺失为 CONTEXT_MISSING，不混淆。名称缺失保持空值，Skill 解释为名称未缓存。更换云连接不影响读取已有本地关联；查询不刷新名称、不更改绑定或上传状态。现有 Viewer 云端刷新名称接口不复用。

当前轮入口文件同时接受旧绑定参数和 `spaces` 子命令，仍只保存身份元数据；同轮旧文件在再次观察时原子升级，失效时清理，无第二份查询 launcher。Prime 共用原生身份读取器，CLI 内部共享解析函数，无新增身份变量、表、缓存、依赖或定时器。详见 [查询契约](../skills/list-project-spaces/references/cli-contract.md)。

## 对话绑定已有项目空间（2026-11-23）

绑定 Skill 仅要求用户明确绑定意图和 Space ID，模型执行 `memos-pm bind --space-id`，不接受 context、Agent、项目或 session 参数。适配器自动提供身份，服务复用已有当前轮身份登记和 bindProject；未绑定只交付身份元数据。宿主缺少原生身份桥时沿既有上下文交付本轮专属入口，入口仅含身份元数据，失效后删除且服务拒绝旧 token；不会创建第二套 bind-context 表。

绑定与创建使用不同入口与状态。绑定不改变创建请求的 state/request/result，不触发创建的整轮排除。只过滤可确认的绑定工具调用及对应结果，调用身份最小控制记录用于重启后的迟到结果关联，Viewer 和上传不呈现。混合业务内容和不确定脚本保留，实时、历史与上传使用同一过滤；已发送审计不改写。新增目标复用 nextTurnOnly，追加而不替换，重复绑定不重置 boundAt 或准入边界，不自动补传历史。详见 [绑定 CLI 契约](../skills/bind-project-space/references/cli-contract.md)。

## 对话创建项目空间（2026-11-22）

独立创建 Skill 仅在用户明确要求时启用，分别一轮补齐缺失的 name、domain，无默认值；两项明确后调用 `memos-pm create --context --name --domain`。项目目录和 Agent 从宿主当前会话身份解析，不由模型提供。未绑定时仅允许身份元数据登记和创建上下文交付，不建立任务轨迹或调用 add/message。

创建复用现有 bindProject 逻辑并追加 Space；创建轮全部目标均不上传，原生轮次和迟到子任务排除持久化。新目标仅接收绑定完成后开始的完整用户轮；既有其他任务继续向原目标正常投递。绑定与新目标轮次边界同事务提交，失败保留云端已知 ID。创建请求并发及重启不自动重发；历史队列不能绕过创建轮排除。此规则仅扩展对话创建入口，Viewer 原有绑定时刻行为保留。详见 [接口与轮次契约](create-project-space.md)。

## 身份、路由与上下文

- `sessionId`：本地 UUID，唯一对应 `(agentType, nativeSessionId)`。
- `conversationId`：当前用户输入轮的本地 UUID，稳定边界为原生 turn ID 或宿主用户提交事件。工具循环不产生新轮。
- 云端 `add/message` 与 `search/memory` 使用 `conversation_id: session.id`，同一宿主会话跨轮次、重试、重启及历史补传保持一致，不使用每轮的本地 `conversationId`。任务状态保留在本地及 `get/status` 查询中，不作为上传参数。
- CLI 必须匹配会话当前轮；缺失或旧轮不回退“最近会话”。
- 项目按工作目录最长路径匹配；同一 Agent＋项目共用 Space 列表，不同 Agent 独立绑定。原生父会话 ID 单独保留。
- 每个 Agent＋项目最多绑定 20 个不同 Space；第 21 个在 Viewer 弹窗提示“单个项目绑定空间不能超过20个”并拒绝创建或绑定。后端两个绑定入口在云请求前校验，SQLite 事务内再次检查；重复绑定不占名额，解绑后可补入。此上限不是 userId 的总空间配额。
- Viewer 轨迹页优先按已保存的项目 ID 分组；未登记项目但已有可靠绝对 `cwd` 的主会话，按完整目录显示本地项目，名称取目录末段，不要求先绑定 Space。同名不同目录分别展示；缺少可靠目录的会话仍列为“未归属项目”。目录分组仅用于展示和筛选，不写入项目表、不改动任务归属或上传空间。
- Codex 主会话目录以原始 `session_meta.cwd` 为准，轮次或工具执行目录不覆盖会话归属。采集对账在源目录可靠且无冲突时纠正历史 `sessions.cwd` 和未登记项目的任务名称，保留会话、任务、Space 与上传批次身份；多个源目录矛盾或与已登记项目冲突时记录诊断并保留原归属。启动后的首次采集即对账，无需等待新消息；旧读取缓存复用现有版本机制升级，正常追加与源文件替换仍分别处理。
- Viewer 通过 Agent 筛选已有项目及目录，可输入 Space ID 后校验追加，或输入 Space 名称并确认后显式创建并绑定。复用 `name/root/spaceId/objectId/agentType`：`bindings` 以 `(objectId,spaceId)` 唯一保存每条关联，`project_agents` 保存项目与已有 `agentType` 的关系。接入已有独立会话时仅迁入对应 Agent 的会话归属，旧独立空间不自动成为新授权；跨云连接或创建结果待确认时整体回滚。
- 列表可以为空；解绑只删除指定关联，最后一个删除后保留 unbound 空标记，避免自动创建替代空间。历史批次及原文保留，新的检索与上传仅使用当前绑定。
- 旧单 Space 数据升级前生成 `memory.sqlite.before-multi-space-*.sqlite` 恢复快照；旧关联及批次目标迁入列表，批次 `spaceId` 列替换为 JSON `spaceIds`，不同时维护两套参数。
- `get/memory` 是单 Space 接口，绑定及过期会话开启刷新按各绑定空间读取第 1 页、10 条，落库后合并概览。主动 search 始终一次请求携带完整 `space_ids` 列表。新增绑定只更新对应 Space 的概览，解绑删除对应缓存；已交付历史消息不回删。
- `/api/context-delivery {sessionId}` 标记已向宿主交付，不代表模型已消费。history 宿主首次交付概览，后续只更新标识；request-view 宿主每次附加本地缓存。读云次数不随工具轮次增加。
- DSH 的动态标识通过 `systemPrompt.context()` 注册为 `memos-project-memory:call-context`（order 220、required、禁止模板插值），按当前 Agent/session 读取隔离缓存；异步 pre-step 登记身份后，由宿主请求前 `refreshContext()` 更新运行快照。适配器不再追加仅含标识的独立 user 消息，也不改写 Skill 目录。
- DSH 的初始概览作为一次性历史资料交付，与动态参数分开。只有观察到同一会话中对应消息 ID 的 `user/message` 提交后才确认 delivered；被拒绝或丢弃的候选不确认。历史快照的替代语义由 DSH 维护，不删除既有会话记录。

## 上传

- 轨迹仅保留真实用户任务、工具调用与结果、助手回复。系统提示、插件/宿主注入内容、权限与运行配置、生命周期、标题生成、交付/上传状态不进入 `traces`，也不进入上传消息。未知且无法识别为上述三类的事件不以 JSON 兜底上传。
- 有效轨迹保留正文及工具名称、参数、结果；DSH 嵌套助手消息正确解析，同一原生用户消息按稳定消息 ID 去重，不按正文去重。Viewer 只读取同一规范化消息，上传状态独立保留在批次管理中。
- `normalizeTaskTrace` 在普通采集、Codex 专属写入与历史导入前筛选任务内容；按结构化来源排除宿主提示、工具定义列表与 Skill 清单，混合消息按块保留。新 `traces.raw` 仅含身份、时间、事件类型等必要元数据及规范化消息，不另存被排除的提示正文。真实工具结果正文视为任务数据，不递归按字段名或提示关键词清理。Skill 调用、参数、结果正文和状态在采集、解析缓存、SQLite 及 Viewer 中完整保留，不生成 Skill 摘要或空控制记录；绑定操作仍按原有控制记录契约处理。
- 上传快照由 `filterUploadTraces` 在本地完整轨迹的副本上生成，保留路径搜索、工具能力查询与业务结果，不修改采集记录。Claude Code、Codex CLI、Cursor CLI、Copilot CLI、WorkBuddy、Prime、DSH 在各自适配目录识别原生 Skill 调用及明确读取 `SKILL.md` 的操作；非 MemOS 自有 Skill 仅在上传侧缩减为技能名、原生调用 ID 和执行状态，并沿用原有完整性校验。公共层负责路由和关联，不启用其他 Agent 的识别规则。OpenCode 适配不受此变更影响。
- MemOS 自有 Skill 的归属复用安装清单（skillFile/skillFiles/files）的路径与哈希；插件包内文件按实际路径确认，不能仅凭同名目录推断。仅从上传副本按来源会话、原生轮次及 call ID 成对排除调用与结果；混合 shell 调用的全部附带输出也排除，包括同一调用里的 search，不拆分正文、不生成 incomplete。独立 search 调用及回包、同一消息的其他独立工具块和文字保留。未知来源和动态路径不猜测归属，来源冲突报错，不关闭其他完整性校验。旧 Skill 投影和解析缓存只在有可核对的原始日志时恢复完整本地记录，日志缺失不能恢复；恢复不改写已发送快照和回执，不自动重传。
- Claude Code 的 Hook 只交付调用上下文及采集通知，正文唯一来源为主/子会话原生 JSONL。专属 `claude_receipts` 仅保存待补读来源、轮次与结束核对信息，完成后删除；轮次和投递状态仍使用现有表。Stop 须等待原生最终回答和其后的 `stop_hook_summary`，子 Agent 使用独立会话身份，不能将其最后回答合成到主会话中。文件缺失时保持待补读，不以 Hook 正文兜底。DSH 与 Codex 的专属采集代码不依赖此模块。
- Claude 的 `tool_use`/`tool_result`、检索与业务工具在本地完整保留，Skill 上传采用上述成对排除或摘要规则，不删除相邻工具或 thinking。Cursor 的普通工具和 Skill 失败都保存实际错误与失败状态，不以整个 Hook 事件作结果兜底；pre/post 及 transcript 优先按可靠原生调用 ID 合并；匿名 Shell 仅在同轮命令与目录唯一对应、双方显式执行参数不冲突时复用 Hook 身份。重复或有歧义的业务操作保留，不按正文去重。
- Cursor 的待补读任务存入 `cursor_receipts`，按本地轮次唯一，保存来源边界、启用窗口和结束通知，不保存整份 Hook 或额外正文副本。Hook 入口只先读文件元数据，绑定准入通过后才读取该时刻已存在的前缀；末尾完整 turn_ended 单独作为可变生命周期标记保存，历史正文哈希仍严格校验；标记保留时跳过，替换时从其原起点读取。旧 receipt 必须重建出与原哈希完全一致的提交快照才能转换。实际读取起点用于区间认领和竞争检查。校验文件身份、稳定前缀、完整行与本轮用户边界，不能选择任意最后一轮或复用已认领区间。所有实时记录沿用入口时间且必须属于同一启用窗口。首次路径缺失时按宿主工作区元数据和准确会话 ID 定位；读取失败保存入口 dev/ino/size 和具体错误，后续重试原区间。没有入口证据时只能根据明确且唯一的原生轮次 ID 恢复，不能按相同问题、最新文件或任意零偏移猜测。
- Cursor 完整轮次依据对应原生区间的 `turn_ended`、此前正文和已知执行结果确认，stop 不直接建批；取消／失败有明确原生状态时允许无回答。原生来源位置与块位置只作为排序证据，补读与 Hook 可靠 ID 合并，工具结果保持调用之后；afterAgentResponse 正文先入库供查看，不触发提前上传；补读时将同一已验证轮次的 Hook 正文作为投影视图，与一条或连续多条原生消息文字核对；允许重叠或乱序 Hook 快照，不消耗或折叠原生消息，正文顺序以原生记录为准，仅删除已匹配副本，保留不匹配内容及原生重复消息。原生记录合并、快照生成和清除 receipt 在同一事务中完成。使用现有同步周期补读，不新增延迟配置、轮询定时器或上传重试队列；文件缺失、半行和来源冲突保持未完成，服务重启后继续。
- 上传通过同一投影生成接口允许的消息：纯文本和可读 thinking 保留原顺序，保留可靠的 `id/chat_time/role_id/role_name`；模型、用量、签名和宿主包装不上传。原生消息 ID 优先，缺少时以既有来源会话和 sourceId 生成稳定消息 ID，拆分消息使用固定块序号。原生发生时间标准化为带时区 ISO；历史无可靠时间不补入库或当前时间，不猜成员。明确无效时间、成员名称缺 ID 会阻塞该批。仅签名的 thinking 不算文案；外层与块内不同 thinking 均保留。
- 原生工具调用块转换为 `tool_calls[{id,type:"function",function:{name,arguments:字符串}}]`，参数对象无损 JSON 序列化，已有字符串不改。多条工具结果逐项生成 `role:"tool"` 与对应 `tool_call_id`；对象、数组、null 结果无损序列化为正文字符串，空结果保留操作，失败状态与实际错误保留。混合消息按块顺序输出，不按正文去重或猜调用身份。Skill 排除和摘要只作用于上传副本；业务工具正文中的 model/usage/signature 字段不按包装清理。
- 上传先基于完整上下文完成关联、包装去重和 Skill 过滤，再校验消息、计算容量和分批；普通、Codex 与历史补传共用投影和校验。必需工具字段缺失时保留本地证据并阻塞批次，不删除操作或虚构参数。一条来源轨迹的全部投影消息匹配后才记投递覆盖；投影为空的 Skill 记录无需发送，不反复建空批次或计入待上传数。旧成功快照仅在匹配视图中标准化时间，不改原快照或回执。上传格式迁移只重建明确未发送任务，旧已尝试但未确认的请求停止自动重试；不改写已接收快照，不自动重发旧数据。
- Codex 外层 `exec` 与内层 `CommandExecution` 同时出现时，仅在同一执行范围、调用返回区间内且输出能逐项对应时去除重复包装；不同调用的相同正文不去重。业务工具、可见 thinking、子 Agent 的任务与结果保留。投递继续关联原始源记录以维护每 Space 回执，首次发送后的正文不重新过滤或改写。
- 旧版数据库首次升级会先生成 `memory.sqlite.before-task-traces-*.sqlite` 恢复快照，再清理旧轨迹并重建尚未获云端接收确认的批次；保留批次重试次数。已接收批次的历史发送记录不改写、不重发，也不会自动删除云端既有数据。
- 上传 POST `add/message`：`user_id`、稳定 profile `agent_id`、当前目标的 `space_ids:[spaceId]`、`messages`、`allow_memory_view:["project"]`、`async_mode:true`。未绑定时不采集、不入库、不建新上传任务，也不自动创建 Space。
- `add/message` 始终省略 `domains`，由服务端使用目标 Space 的全部已登记领域作为候选；上传不读取领域映射、不调用 `list/domains`，也不因本地缺映射而阻塞。`space_domains` 按 `(baseUrl,spaceId)` 保存领域名列表，仅供空间绑定校验：新建时保存选择，绑定已有空间时缺失或为空才调用 `list/domains`，空领域不能完成新绑定。外部领域不受本机自定义名称的 24 字限制。上传不传 `session_id` 或任务状态，不添加未经确认的幂等头。
- 不再创建、冻结或读取投递领域快照；旧数据库已有的 `batch_deliveries.domains` 列保留兼容但不使用，不为此清库。实时上传和历史补传均使用同一消息快照，重试不受映射变化影响。旧已尝试且尚未确认的请求在上传投影升级时停止自动重试，保留原消息、次数及回执，避免变更请求后自动重发；成功回执不改写。解绑取消未发送的阻塞投递，重绑不恢复原队列。
- `40089` 沿用普通发送失败处理及既有次数上限，不触发上传侧领域补查、缓存刷新或专属恢复。
- 暂停期间继续本地采集。与暂停时段有重叠的整轮对话通过项目页手动上传历史，恢复后新开始的轮次自动上传。暂停时段保存在本地，适用于服务重启和延迟补读。
- 每批每个 Space 最多发送两次，发前持久化次数。接收必须 `success:true` 且含 `task_id`，随后 `uploaded=true`。处理失败保留此确认；两次失败终止，重启/暂停恢复不重置。
- 首次发送持久化目标列表；重试仅保留快照内仍绑定的目标，不向已解绑空间发送。不因后来新增 Space 而重发已接收批次。
- 采集只写入轨迹，不创建上传任务。宿主明确结束整轮任务后，按 `conversationId` 读取完整有序消息，生成一次不可变上传快照；上传端直接使用该快照，不再次拼接。重复结束通知、重复回放和服务重启不重复建任务。
- 正常完成轮次保留一个原始上传快照；历史补传或绑定时间裁剪通过补充批次投递缺失内容，保留原快照。实时整轮超过配置容量时保留为 blocked，不截断；显式历史补传按下述容量规则拆批，超大单条本地保留并静默跳过。
- 轮次批次升级先生成 `memory.sqlite.before-turn-batches-*.sqlite` 备份；从未发送的旧采集片段恢复为待确定轨迹，在收到真实结束信号后创建整轮任务。已尝试/已接收的旧批次保留原发送历史，不重组重发。
- 采集和上传通路不创建 Space。Viewer 中只有用户明确确认新建时才调用 `create/space`，同时传 `space_name` 与 `domains:[{domain}]` 登记所选领域；Domain 为本地固定的“编程 / 办公 / 自定义”，未选不可创建，自定义名称去除首尾空白后须为 1–24 个 Unicode 码点，前后端均校验，不调用 `list/domains` 获取选项；直接使用返回的 ID、名称复用既有绑定事务，不额外查询 `get/space`。创建成功但绑定失败返回已知 `spaceId`，供普通绑定恢复；创建结果未确认不自动重试。历史创建结果不明的遗留记录仅保留审计。

## 绑定准入与历史补传

- 项目选择只发现已完成接入的 Agent；各 Agent 独立保留服务内存项目缓存。首次无缓存才发现，显式刷新才重新读取目录/项目索引并合并新增项。页面重绘、绑定和解绑不清空列表、不触发项目重扫。项目页单独读取绑定关系，不等待会话标题、轨迹或全部宿主版本探测。
- 新 Agent 项目首次绑定后后台扫描历史；未绑定不读取历史正文。已有 scope 的状态刷新只合并 SQLite 中的已完成轮次，不因新增 Space 或新轮次重扫宿主历史。手动“扫描历史”可更新原生来源索引，扫描不上传。服务重启后，项目元数据缓存首次读取重建，已有 scope 的历史概览先使用 SQLite 记录，不自动重扫未导入的宿主历史。

- `project_agents.id` 是 Agent＋项目 scope；不增加独立 enabled 开关。当前 Space 列表非空才启用记忆。`bindings.boundAt` 记录各目标加入时刻，`capture_windows` 记录启停边界。
- 未绑定只发现项目元数据。适配器预检与服务端同时守住采集、注入、检索、上传入口；未启用是正常状态，不写诊断事件。已解绑的会话保留在 Viewer 中。
- 自动采集只接受当前启用窗口内有可靠时间的内容。实时回调缺少原时间时可用接收时间；历史回放不得补当前时间。新增 Space 只自动接收其绑定后的内容。
- 历史扫描目录及来源索引与上传成功分开。扫描不把历史正文写入 SQLite，显式上传才导入完整轮次。无法读取全部原生历史时必须展示范围提示。
- `batch_traces` 关联批次与来源轨迹；`batch_deliveries` 按批次＋云连接＋Space 保存尝试次数、接收确认和处理状态。成功目标不重复上传，失败目标可通过历史按钮补传。
- 解绑取消对应未发送目标；已发网络请求仍记录真实回执。重新绑定不恢复已取消队列，同一 Space 既有成功回执持续有效。
- 迁移备份为 `memory.sqlite.before-agent-bindings-*.sqlite`。只迁移明确存在的 Agent 关联，保留历史内容与已发送批次，不凭旧项目目录自动启用其他 Agent。

## CLI JSON

成功：`{ok:true,status:"FOUND"|"EMPTY",data:{content:string},error:null}`。
失败：`{ok:false,status:"INVALID_QUERY"|"CONTEXT_MISSING"|"UNAVAILABLE",data:null,error:{message:string}}`。

`data.content` 与概览共用条目格式，只包含云端返回的 `topic_summary` 和 `topic_description`。检索直接返回条目正文；没有有效文案时返回 `EMPTY` 和空字符串。新的成功检索记录只在 `recalls.content` 保存这份正文。

## Viewer 轮次分页

`GET /api/sessions/:id?unit=turn&page=1&size=10` 返回完整轮次的 `groups: [{ id, traces }]`，`total` 为分组数量；以存储的 `conversationId` 归组。缺少轮次标识的记录独立保留，避免错误合并。省略 `unit` 时沿用逐条轨迹分页。此变更不修改采集和上传内容。

## Viewer 轨迹分类

显示类型为 `user`、`tool use`、`tool result`、`thinking`、`answer`，均采用独立白色折叠框。依据消息块类型及显式 reasoning/thinking 字段、analysis channel 分类；不从自然语言猜测思考与回答的边界。宿主未提供思考内容时不生成 thinking，明确的 redacted_thinking 只显示不可读提示。图片、附件保持所属消息分类，工具错误属于 tool result。此分类只改变展示，不重写已存消息或上传内容。

## 轨迹确定信号

- 普通 Hook：Stop/stop、Copilot agentStop；SessionEnd 可结束会话中剩余轮次。SubagentStop 只结束对应子会话。Cursor 例外：stop/sessionEnd 仅通知专属读取器，须核对对应原生 turn_ended 与完整正文后再结束轮次；已登记子任务按精确父轮次关联等待，关联缺失时不猜测。
- DSH：turn/end；Pi：agent_settled；Prime：agent_end；Cline：afterRun。
- OpenCode V1/Kilo：session.idle/status=idle；V2：execution succeeded/failed/interrupted，shutdown 中断留待恢复。
- 工具结束、模型步骤结束不确定整轮轨迹。所有最终记录须先保存，再发送 turn-end。
