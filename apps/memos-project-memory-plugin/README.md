# MemOS 项目记忆插件

独立本地服务、SQLite、Viewer、Agent 适配与 `memos-pm search`。云端负责记忆整理；插件负责采集用户任务、工具执行和助手回复，按 Agent＋项目绑定的 Space 列表上传与检索。

当前为开发验证版：公共链路及独立安装已通过 Mock 验证，**尚未达到全部 22 宿主与真实 MemOS 的完整验收条件**。具体缺口见 [兼容性](docs/compatibility.md) 和 [验证记录](docs/verification.md)。未发布 npm。

## 源码部署（开发阶段）

需要 Node.js ≥24.12（本次实际验证 26.4.0）。在本目录：

```sh
npm ci
npm run build
npm link
npm run viewer
```

`npm run build` 仅编译 TypeScript 到 `dist/`，不生成安装包。`npm link` 将当前源码目录链接到全局 npm，并注册 `memos-pm` 命令；可用 `command -v memos-pm` 检查。Agent 启动环境需能找到该命令。

构建后，重新运行 Viewer 或新的 CLI 调用会核对后台服务的 API 版本与构建标记，必要时在同一端口优雅更新受管实例，保留原 SQLite 数据。浏览器遇到旧版服务会明确提示更新，不把旧字段误显示为“未绑定 Space”或“待识别”。

Viewer 会启动独立本地服务并打开浏览器。也可用 `npm start` 前台启动，终端显示访问地址。服务只监听 `127.0.0.1`。默认数据目录 `~/.memos-project-memory`；配置 API 基址和 Key 后，在 Viewer 选择 Agent、下拉选择已有本地项目，选择“新建 Space”输入名称并确认，或切换“绑定已有 Space”输入 Space ID，完成绑定并安装相应 Agent 接入。项目名称和目录由记录自动取得，无需手动创建项目。

项目发现只读取宿主元数据中的项目名称和目录，供“项目与空间”页面选择。绑定对象是 **Agent＋项目目录**；同一目录的不同 Agent 独立绑定，项目按最长目录匹配。未绑定时，hook 提前返回，不采集会话正文、不创建会话或轨迹、不注入上下文、不上传或检索。

项目选择只列出已完成接入配置的 Agent，各 Agent 独立缓存项目列表。首次选择且无缓存时发现项目；切换 Agent、返回页面及绑定操作复用缓存，点击“刷新”才对当前 Agent 重新做轻量发现并合并新增项目，保留已有选项和选择。缓存保存在后台服务内存中，浏览器刷新可以复用，服务重启后首次选择重新发现。项目页不执行宿主版本探测，也不等待会话轨迹或标题读取。

新项目首次绑定后在后台扫描历史，不阻塞本地项目列表。已知项目的状态刷新只合并 SQLite 中已完成轮次的记录，不重新扫描宿主历史；未绑定项目不读历史正文。需要重新发现宿主旧会话时，在绑定关系中点击“扫描历史”；扫描与上传分开，扫描不会自动上传。服务重启后已有项目先使用 SQLite 中的历史索引，未导入的宿主历史可手动重新扫描。

绑定第一个 Space 后，从绑定时刻起采集新内容，包括进行中会话的新增部分。最后一个 Space 解绑后停止记忆操作，已有轨迹保留且不再更新；重新绑定从新的时间起点恢复，不自动补采中间断开的内容。Skill 保持安装，但没有当前有效绑定上下文时拒绝执行。

“绑定关系”每行展示一个 Agent＋项目，最后一列为“历史会话上传”：扫描未完成显示 `--`；存在尚未上传到当前 Space 的历史时显示可用的“上传历史”；全部目标已接收则显示灰色禁用的“已上传历史”。上传受暂停、配置或发送错误阻碍时，显示红色禁用的“上传历史失败”并说明原因。新增 Space 后按钮重新可用，只补传缺失的目标与内容。历史扫描只保存内存索引，点击按钮才将历史正文入库并排队；重复点击不重复提交已成功目标。无法读取原生历史的宿主会明确提示仅包含插件已采集的会话。

Space 数量可打开抽屉查看、复制编码或解绑。解绑仅删除本地关联并取消该目标尚未发送的任务，保留云端 Space、已有轨迹和发送回执。正在进行的网络请求无法撤回，其响应仍用于记录真实发送结果。

Hook 安装器在 Homebrew 环境优先保留指向当前 Node 的稳定 `opt/<formula>/bin/node` 入口，避免固定到具体 Cellar 版本；无匹配入口时沿用当前 Node 路径。源码目录移动后，在 Viewer 中执行“更新接入配置”更新脚本路径。

源码开发可执行 `npm run dev`。宿主接入的安装/修复/卸载都在 Viewer 操作；不会自动改动所有宿主配置。宿主须重启，原生信任确认仍由宿主处理。DSH 接入会写入 `$DSH_HOME/cordis.patch.yml`（默认 `~/.dsh/cordis.patch.yml`）的插件专属配置块，保留其他配置；安装后直接 `dsh web` 等正常启动即可。

仅在用户选择“新建 Space”并确认后，插件才创建空间并自动绑定所选 Agent＋项目；采集和上传不自动创建 Space。创建成功但绑定失败时保留返回的 Space ID，可切换已有绑定方式继续；创建结果未确认时不自动重试。暂停只阻止发送，已绑定项目的采集继续；恢复不会自动重试终止失败任务。上传按 Space 独立记录接收与处理结果，失败 Space 不影响其他目标，也不导致成功目标重复发送。旧库迁移先备份，保留历史内容与发送回执，不自动补传旧内容。

## 任务轨迹

列表按用户轮次归组，每轮一个白色摘要框；点击打开右侧详情。user、tool use、tool result、thinking、answer 五类按顺序折叠展示，展开后可查看完整内容，长文本在框内滚动。分页按轮次进行，不拆开同一轮。

采集过程中只保存轨迹；宿主结束整轮任务后，创建一个上传批次。上传直接使用确定后的完整消息快照，不重复拼接。重复结束通知不会重复建批。

会话页只展示用户任务、执行过程、助手回复；采集入库与上传使用同一筛选规则。插件注入和宿主临时提示、运行状态不作为项目记忆上传。上传状态单独记录在批次中。旧数据库升级时会先备份，再清理非任务轨迹并修正待上传内容。

## CLI

唯一公开业务命令：

```sh
memos-pm search --session-id <宿主提供的ID> --conversation-id <当前用户轮ID> --query "接口约定"
```

`FOUND` / `EMPTY` 退出 0；`INVALID_QUERY` / `CONTEXT_MISSING` / `UNAVAILABLE` 退出 1。stdout 为单个 JSON 对象。不要猜测标识或复用旧轮标识；共享 Skill 随适配器部署。

一条 search 命令由本地服务补齐项目的全部 `space_ids`，只发起一次云端检索，无需按 Space 重复调用，也不增加模型侧 Space 参数。

## Mock 与验证

在独立终端：

```sh
npm run mock
MEMOS_PM_DATA_DIR=/tmp/memos-project-memory-demo npm run viewer
```

测试 Viewer 中填 API 基址 `http://127.0.0.1:8711/api/openmem/v1`、Key `mock-key`。Mock 主题是固定测试数据，不执行记忆抽取；Mock 重启清空内存数据，应配合新的测试数据目录。不要把 Mock 空间绑定到生产数据目录。

```sh
npm test
npm run typecheck
npm run lint
npm run build
```

`lint` 当前执行源代码语法静态检查；类型检查独立执行。
