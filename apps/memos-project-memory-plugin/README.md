# MemOS 项目记忆插件

云连接支持算法接口与工程接口。接口类型与服务地址沿用插件配置，用户在 Viewer 中管理 API Key。算法接口创建和写入时默认传入当前接口要求的项目 ID `test1`，也可显式配置其他项目 ID；配置方法见下方云服务访问文档。旧配置按工程接口保留。参数映射、连接切换和验证边界见 [云服务访问配置](docs/cloud-access.md)。

项目概览按 Space 缓存在 SQLite：新建／绑定时立即拉取；可靠会话开启信号在缓存超过6小时或未获取时触发更新。阻塞型宿主等待新缓存，非阻塞型先使用旧缓存；普通 Hook 仅读取 SQLite，解绑同步删除对应缓存。详见 [概览缓存契约](docs/overview-cache.md)。

独立本地服务、SQLite、Viewer、Agent 适配与 `memos-pm search/create/bind/spaces/unbind`。云端负责记忆整理；插件负责采集用户任务、工具执行和助手回复，按 Agent＋项目绑定的 Space 列表上传与检索。

当前为开发验证版：**尚未达到全部 22 宿主与真实 MemOS 的完整验收条件**。具体缺口见 [兼容性](docs/compatibility.md)。未发布 npm。

## 源码部署（开发阶段）

需要 Node.js ≥24.12（本次实际验证 26.4.0）。在本目录：

```sh
npm ci
npm run build
npm link
npm run viewer
```

`npm run build` 仅编译 TypeScript 到 `dist/`，不生成安装包。`npm link` 将当前源码目录链接到全局 npm，并注册 `memos-pm` 命令；可用 `command -v memos-pm` 检查。Agent 启动环境需能找到该命令。

构建后，重新运行 Viewer 或新的 CLI 调用会核对后台服务的 API 版本与构建标记，必要时在同一端口优雅更新受管实例，保留原 SQLite 数据。浏览器遇到旧版服务会明确提示更新，不把旧字段误显示为“未绑定 Space”或“待识别”。

Viewer 通过 URL 片段（如 `#projects`、`#sessions`）记录当前主页面，浏览器刷新和前后退保持目标页面；不另存页面状态副本。

Viewer 会启动独立本地服务并打开浏览器。也可用 `npm start` 前台启动，终端显示访问地址。服务只监听 `127.0.0.1`。默认数据目录 `~/.memos-project-memory`；保存 API Key 后，在 Viewer 选择 Agent、下拉选择已有本地项目，选择“新建 Space”输入名称，选择 Domain 后确认（编程、办公或自定义；自定义名称去除首尾空白后不超过 24 个字符），或切换“绑定已有 Space”输入 Space ID，完成绑定并安装相应 Agent 接入。项目名称和目录由记录自动取得，无需手动创建项目。 新建成功后保存 Space 与 Domain 的本地映射；首次绑定已有空间且缺少映射时，读取其领域列表并保存。空领域空间须先在云端配置后再绑定。领域映射用于绑定校验；上传始终省略 `domains`，由服务端使用目标 Space 的全部已登记领域，本地缺少映射不阻塞上传，也不会在上传时额外查询领域。

项目发现只读取宿主元数据中的项目名称和目录，供“项目与空间”页面选择。绑定对象是 **Agent＋项目目录**；同一目录的不同 Agent 独立绑定，项目按最长目录匹配。每个 Agent＋项目最多绑定 20 个不同 Space，第 21 个弹窗提示“单个项目绑定空间不能超过20个”并拒绝创建或绑定；重复绑定不占名额，解绑后可补入。未绑定时，hook 不采集会话正文、不创建任务会话或轨迹、不注入记忆概览、不上传或检索；仅交付下述创建功能的纯身份上下文。

项目选择只列出已完成接入配置的 Agent，各 Agent 独立缓存项目列表。首次选择且无缓存时发现项目；切换 Agent、返回页面及绑定操作复用缓存，点击“刷新”才对当前 Agent 重新做轻量发现并合并新增项目，保留已有选项和选择。缓存保存在后台服务内存中，浏览器刷新可以复用，服务重启后首次选择重新发现。项目页不执行宿主版本探测，也不等待会话轨迹或标题读取。

新项目首次绑定后在后台扫描历史，不阻塞本地项目列表。已知项目的状态刷新只合并 SQLite 中已完成轮次的记录，不重新扫描宿主历史；未绑定项目不读历史正文。需要重新发现宿主旧会话时，在绑定关系中点击“扫描历史”；扫描与上传分开，扫描不会自动上传。服务重启后已有项目先使用 SQLite 中的历史索引，未导入的宿主历史可手动重新扫描。

绑定第一个 Space 后，从绑定时刻起采集新内容，包括进行中会话的新增部分。最后一个 Space 解绑后停止记忆操作，已有轨迹保留且不再更新；重新绑定从新的时间起点恢复，不自动补采中间断开的内容。检索 Skill 保持安装，但没有当前有效绑定上下文时拒绝检索；创建 Skill 使用独立的当前宿主身份上下文。

“绑定关系”每行展示一个 Agent＋项目，最后一列为“历史会话上传”：扫描未完成显示 `--`；存在尚未上传到当前 Space 的历史时显示可用的“上传历史”；全部待处理内容完成后显示灰色禁用的“已完成”。暂停时显示“上传暂停”；发生可补传的失败时显示可点击的“重试上传”，配置或其他阻碍使当前无法提交时显示禁用的“上传历史失败”并说明原因。扫描失败可点击“重试扫描”。新增 Space 后按钮重新可用，只补传缺失的目标与内容。历史扫描只保存内存索引，点击按钮才将历史正文入库并排队；重复点击不重复提交已成功目标。无法读取原生历史的宿主会明确提示仅包含插件已采集的会话。

Space 数量可打开抽屉查看、复制编码或解绑。解绑仅删除本地关联并取消该目标尚未发送的任务，保留云端 Space、已有轨迹和发送回执。正在进行的网络请求无法撤回，其响应仍用于记录真实发送结果。

Hook 安装器在 Homebrew 环境优先保留指向当前 Node 的稳定 `opt/<formula>/bin/node` 入口，避免固定到具体 Cellar 版本；无匹配入口时沿用当前 Node 路径。源码目录移动后，在 Viewer 中执行“更新接入配置”更新脚本路径。

源码开发可执行 `npm run dev`。宿主接入的安装/修复/卸载都在 Viewer 操作；不会自动改动所有宿主配置。宿主须重启，原生信任确认仍由宿主处理。DSH 接入会写入 `$DSH_HOME/cordis.patch.yml`（默认 `~/.dsh/cordis.patch.yml`）的插件专属配置块，保留其他配置；安装后直接 `dsh web` 等正常启动即可。

仅在用户选择“新建 Space”并确认后，插件才创建空间并自动绑定所选 Agent＋项目；采集和上传不自动创建 Space。创建成功但绑定失败时保留返回的 Space ID，可切换已有绑定方式继续；创建结果未确认时不自动重试。暂停期间已绑定项目的采集继续，但与暂停时段重叠的完整轮次转为手动上传；恢复后这些轮次需通过“上传历史”补传，后续未跨越暂停时段的新轮次恢复自动上传。恢复不会自动重试终止失败任务。上传按 Space 独立记录接收与处理结果，失败 Space 不影响其他目标，也不导致成功目标重复发送。旧库迁移先备份，保留历史内容与发送回执，不自动补传旧内容。

## 历史按容量分批上传

后台上传字节上限（`uploadMaxBytes`）控制每次 `add/message` 请求体的 UTF-8 字节数，包含 JSON 结构和路由字段；旧配置默认补入 39000 字节。上限须为正整数，不另设历史专用阈值。组批和实际发送复用同一个请求体构造方法，未发送内容按当前配置核对，已经尝试发送的快照不改写。

点击“上传历史”前重新读取当前绑定的待处理数量；超过配置的“历史上传确认条数”（`historyUploadConfirmCount`，默认100）时弹窗确认，同一记录对应多个空间不重复计数，取消不提交。确认后按原始会话时间从早到晚逐会话读取、准备批次，一个会话内部可以跨轮分批，不混合不同会话的云端身份。每批处理完成后继续后续批次，复用现有同步周期；整个过程中按钮为禁用的“上传中…”，全部处理完成显示“已完成”。

单条消息连同必要请求字段仍无法放入一批时，静默跳过发送，不弹窗、不显示容量错误；本地正文不截断、不删除。为保持工具关联，必要时一并跳过对应调用及结果。内部跳过状态不伪造成功回执，也不继续计入待处理数。网络、鉴权和云端处理失败仍正常显示，已成功空间不重发。

暂停后保留当前进度，恢复通过现有同步周期继续；任务只使用点击时授权的空间及绑定关系，新增空间不自动加入，解绑后重绑不恢复旧授权。重启后保留已准备批次与回执；尚未读取的原生历史沿用现有显式扫描／上传入口，不在启动时自动扫描。再次上传只处理缺失内容。此前从未发送的容量阻塞历史批次在再次显式上传时按新规则处理；既有发送快照保持不变。

## 任务轨迹

顶部按 Agent、项目和时间选择范围；左侧为会话列表，右侧连续阅读按用户轮次归组的轨迹。用户问题和回答直接展示，thinking、tool use、tool result 等执行过程折叠呈现。展开后可查看完整内容，分页按轮次进行，不拆开同一轮。

Claude Code 的正文仅来自原生会话 JSONL；Hook 只负责上下文注入、轮次通知和提供主/子会话文件路径，不再额外合成用户问题、工具结果或最终回答。Claude 独立补读模块接入现有同步周期，等待最终回答和 Stop 完成标记落盘后再生成上传批次；文件暂不可读时保留待补读通知，服务重启后继续。DSH 的实时扩展事件与 Codex 的 rollout 读取器独立保留。

采集过程中只保存轨迹；宿主结束整轮任务后，创建一个上传批次。上传直接使用确定后的完整消息快照，不重复拼接。重复结束通知不会重复建批。

会话页与上传共用入库前筛选后的任务轨迹：保留用户和 Agent 的文字、可读 thinking、实际工具调用及结果、子 Agent 的任务与执行过程，包括主动读取 Skill、路径查找、失败重试和 `memos-pm search`。只按明确的宿主来源与消息块类型排除 system prompt、注入上下文、工具定义列表、Skill 清单和运行配置，不凭正文关键词或工具名称删除操作。混合消息按块保留任务内容，真实工具结果正文不作为宿主提示重新筛选。`raw` 仅保存必要来源元数据与规范化消息，工具失败不再用整份 Hook 事件兜底。Codex 执行事件能逐项证明外层返回只是重复包装时，上传仅保留实际执行结果；未知包装保守保留。实时上传和历史补传共用消息过滤与投影，首次发送后的快照保持不变。实时轮次仍保留整轮快照；历史按下述配置容量分批，超大单条静默跳过发送，本地完整保留。

Cursor 的 Hook 及时保存用户输入、工具调用、结果和 afterAgentResponse 正文。首次 Hook 缺少 transcript 路径时，通过宿主项目元数据和准确会话 ID 定位；提交时分别记录稳定正文边界与可被续聊替换的末尾结束标记，读取失败保留入口文件元数据供重试，缺少入口证据时只允许凭明确原生轮次 ID 恢复。stop/sessionEnd 只登记收尾通知，在对应区间的完整 JSONL 消息和 turn_ended 均落盘、已知工具及子任务结束后，才在同一事务内保存正文、生成快照并清除待补读记录。复用现有同步周期，不按固定时长等待；长回答半行、文件缺失或来源矛盾保持待核对，重启后继续。同一已验证轮次的 Hook 回答作为正文投影视图，与一条或连续多条原生正文核对，正文顺序以原生记录为准，仅移除已对应的副本；不匹配的任务正文保留。来源位置合并原生文字与可靠 ID 对应的 Hook 操作；无 ID 的 Shell 仅在同轮命令、目录唯一对应且显式执行参数不冲突时关联，实时、详情和历史补传共用顺序；无法证明对应关系的无 ID 内容保守保留，不按正文去重。更新接入配置后 preToolUse 覆盖全部工具，并接入 subagentStart/subagentStop，保留其他用户 Hook。旧 pending 仅在重建提交快照哈希完全一致时转换来源边界；不重写或重传已发送批次。

Claude Code、Codex CLI、Cursor CLI、GitHub Copilot CLI、WorkBuddy、Prime Agent、DeepSeek Harness 对已识别的 Skill 调用及明确的 Skill 文件读取只保存技能名、调用 ID 和执行状态，不保存技能正文或其 `raw` 副本。过滤规则分别位于对应适配目录，覆盖实时采集和已支持的历史读取。普通业务工具结果不变；缺少调用身份或 Skill 与业务输出无法拆分时，保存不完整摘要并阻止上传。动态脚本构造的读取路径不作猜测；不自动清理旧数据库、旧缓存或改写已发送快照。OpenCode 保持原有适配行为。

文本上传保留纯文案、可读 thinking 和可靠的消息 ID、实际发生时间及成员信息，不上传签名、模型、用量和宿主包装。工具调用转换为标准 function 格式，多条结果按可靠调用 ID 拆分，对象正文无损序列化；字段不完整时保留本地轨迹并阻止该批上传。空文本和仅含签名的 thinking 不生成消息，空工具结果仍保留操作。实时和历史上传共用规则，既有已发送快照及回执保持不变，历史缺失的时间和成员不编造；随机 userId 沿用原有身份体系。

## Viewer 页面职责

运行概览集中展示本地服务、云连接配置、自动上传状态、统计与需处理事项；只有一处暂停／恢复上传控制，不需要手动同步。页面右上角刷新从本地服务重新读取状态。诊断记录作为概览页标签，只列云服务调用失败；点击“查看”在右侧展示关联会话ID、轮次ID、接口与脱敏后的错误响应，支持复制和导出。超时没有响应时明确说明，不伪造返回。诊断从新版启用后开始记录，旧纯文本日志保留但不混入列表。

左下角设置抽屉仅管理云连接。项目与空间沿用现有新建、绑定及历史补传流程；会话轨迹沿用原版筛选与阅读布局。Agent 接入桌面宽屏每行四张卡片，中屏两张、手机一张，卡片字段与安装、更新、卸载操作保持原样。

## CLI

检索命令：

```sh
memos-pm search --session-id <宿主提供的ID> --conversation-id <当前用户轮ID> --query "接口约定"
```

`FOUND` / `EMPTY` 退出 0；`INVALID_QUERY` / `CONTEXT_MISSING` / `UNAVAILABLE` 退出 1。stdout 为单个 JSON 对象。不要猜测标识或复用旧轮标识；共享 Skill 随适配器部署。

检索成功时，`data.content` 返回按条目排列的摘要与描述。所有主题均缺少有效文案时返回 `EMPTY` 和空字符串。本地概览缓存按 Space 保存同样格式的正文，交付时合并并添加一次标题与说明。

一条 search 命令由本地服务补齐项目的全部 `space_ids`，只发起一次云端检索，无需按 Space 重复调用，也不增加模型侧 Space 参数。

用户明确要求在当前对话项目创建 MemOS 空间时，使用独立的 `memos-create-project-space` Skill。名称不明确时先单独一轮询问名称，领域不明确时再单独一轮询问领域；两项都由用户明确后才执行，无默认值、不再追加确认：

```sh
memos-pm create --context '<本轮宿主交付的创建标识>' --name '用户明确的名称' --domain '用户明确的领域'
```

创建命令不接收项目路径或 Agent 参数；服务按宿主 session 的项目目录定位，工具临时切换目录不会改变目标。项目未绑定也可交付纯身份创建上下文，不开启轨迹采集或检索；此为未绑定早退规则的身份元数据例外。创建后追加 Space，不替换已有绑定，沿用最多 20 个空间与 Domain 校验规则。

对话创建命令所在轮整轮不上传，包括已经保存的输入与迟到子任务结果；新空间只接收绑定成功后开始的完整用户轮，其他进行中会话的后半轮不会补传给新空间。排除与准入边界持久化，重启后继续生效。历史扫描不会自动上传，历史排队也不能绕过创建轮排除。Viewer 原有绑定时间行为保留。

`CREATED` 退出 0，其他创建状态退出 1。云端创建成功但绑定失败返回 `BINDING_FAILED` 和已知 Space ID；网络或响应丢失返回 `CREATE_UNCERTAIN`，不自动重试。相同当前轮请求复用持久化结果，不重复创建。接入安装／更新会部署检索、创建、绑定、查看空间和解绑五个 Skill；更新后按宿主要求重启或重新加载。详见 [创建 CLI 契约](skills/create-project-space/references/cli-contract.md)。

## 对话绑定已有 Space

用户明确要求将当前对话项目绑定到某个 Space ID 时，使用 `memos-bind-project-space` Skill：

```sh
memos-pm bind --space-id '用户提供的 Space ID'
```

无需模型填写上下文、Agent、项目目录或会话标识。Codex/Copilot/DSH 使用原生会话环境，Claude 使用宿主持久环境文件，Cursor/Grok 和 OpenCode v1/Kilo 使用原生工具环境桥接，Prime 复用原生会话读取器。其余宿主通过已有身份上下文渠道交付本轮专属 Node 入口，只替换 Space ID；入口文件仅含路由元数据，轮次结束或下一用户轮到来时删除，旧身份在服务端也被拒绝。无可靠身份时拒绝执行，不猜测最近会话或工具工作目录。各宿主的实机验收范围见[兼容性说明](docs/compatibility.md)。

绑定追加已有 Space，不调用创建接口；重复绑定返回 `ALREADY_BOUND`，不重置上传起点。复用现有权限、领域与 20 个空间上限校验。新增空间从绑定完成后开始的完整用户轮接收，不自动补传历史；已有空间的正常业务继续。

明确的独立绑定工具调用及其可靠 ID 对应结果不进入会话展示或上传，仅保留处理迟到结果所需的调用身份元数据。混合脚本或无法证明对应关系的内容保守保留，不按正文关键词删除业务。首次发送后的快照保持不变；旧解析缓存不强制重放或清理，新解析内容应用过滤。更新接入配置后，按宿主要求重启或重新加载绑定 Skill。详见 [绑定 CLI 契约](skills/bind-project-space/references/cli-contract.md)。

## 对话查看当前项目的空间

用户问“这个项目关联了哪个空间／项目／组织”“当前记忆保存在哪里”等问题时，`memos-list-project-spaces` 按上下文理解 MemOS 绑定查询意图，不要求准确说出 Space：

```sh
memos-pm spaces
```

命令不接受参数，与绑定命令共用当前宿主身份解析和冲突校验。缺少原生身份桥的宿主复用同一个本轮专属入口，执行其 `spaces` 分支，不新增身份变量、目录或数据表；旧的绑定调用形式保持可用。

只读本地 SQLite，返回当前 Agent＋项目绑定的空间名称和 ID，不依赖云端 Key，也不刷新云端名称。`FOUND` 和 `EMPTY` 退出0；未登记或已解绑返回空列表，身份缺失或过期返回 `CONTEXT_MISSING`，不误报成未绑定。名称未缓存时 Agent 显示“名称未缓存”，保留完整 ID。查询不修改绑定、名称或上传状态，也不自动创建或绑定空间。

安装／更新会部署查看空间 Skill，按宿主要求重新加载。查询 API 与 Viewer 原有会联网刷新名称的空间抽屉接口分别保留，详见 [查看空间 CLI 契约](skills/list-project-spaces/references/cli-contract.md)。

## 对话解除空间关联

用户明确要求“解绑这个空间”“取消与这个项目／组织的关联”，并提供 Space ID 后，使用解绑 Skill `memos-unbind-project-space`：

```sh
memos-pm unbind --space-id '用户指定的 Space ID'
```

只需 Space ID。沿用当前 Agent＋项目身份，不传目录或 context；本轮专属入口复用同一个文件的 `unbind` 分支，绑定和查询调用保持兼容。只操作本地 SQLite，不依赖云端 Key，不删除云端空间或其他项目关联。返回 `UNBOUND` 与解绑前缓存名称、解绑后剩余空间；未绑定或重复请求返回 `NOT_BOUND`，均退出0。身份、参数或服务错误退出1，不自动重试。

复用已有解绑事务取消目标未完成的投递；已在网络中的请求无法撤回，仍保存真实回执。最后一个空间解绑后关闭采集窗口，停止该 Agent＋项目的记忆操作；历史轨迹和回执保留，重新绑定不自动恢复已取消队列。明确的独立解绑工具调用及对应结果沿用现有过滤，同轮业务保留，动态混合脚本无法可靠拆分时保守保留。更新接入配置并重新加载解绑 Skill 后使用，详见 [解绑 CLI 契约](skills/unbind-project-space/references/cli-contract.md)。
